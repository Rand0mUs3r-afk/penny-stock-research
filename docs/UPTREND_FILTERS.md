# Controlled uptrend filter comparison

This adds a separate manually triggered Uptrend filter comparison workflow on experiment/uptrend-vwap-only. Main and the existing Yahoo coverage and backtest pilot workflow are unchanged. Select this experiment branch when dispatching.

A is the uptrend-only baseline. B adds cumulative session volume at the completed signal time divided by average cumulative volume through that exact New York clock time across the preceding 20 exchange-calendar sessions; minimum ratio is 2. C adds close above candle-typical-price session VWAP and VWAP higher than three completed bars earlier. VWAP is only a trend filter, never a VWAP-reclaim entry. Original uptrend rules must still emit a signal. Original stop, score, next-bar execution, targets, fees, spread/slippage assumptions, account settings and allocation limits remain unchanged. The implementation temporarily supplies a filtered scanner to the existing engine and restores it after each independent run.

The source pipeline downloads once. Comparison reloads only accepted listed symbols' saved raw CSVs, validates sessions again, and hashes inputs. All variants use identical eligible bars and each starts with the same configured equity. Twenty earlier complete calendar sessions with matching time slots are required for every evaluated symbol/day, including A. No warmup trades occur. Missing previous sessions or early closes that lack required time slots exclude the current symbol/day from ALL variants. This is intentionally conservative and biased toward complete/liquid histories. Full-session validation itself uses end-of-session data quality, so this remains an exploratory retrospective complete-session sample, not a point-in-time selection simulation.

Use the new workflow with default 59 calendar days including warmup, limit 10, allocation 300, feed sip, blank start_date. About 20 sessions are consumed before evaluation begins. Actual dates and sample eligibility are reported. For older history enter start_date, e.g. 2023-01-01; existing Alpaca access checks, corporate-action exclusions and long-range scan caps remain. Symbols may have insufficient history, in which case no results are fabricated. Data providers must remain consistent within a symbol's window. Yahoo metadata/actions are still needed by the source pipeline. OTC remains coverage-only.

Artifacts: comparison.csv, experiment.json with source hashes and provenance, eligibility.csv, and A_baseline/B_rvol/C_rvol_vwap folders with run.json, SUMMARY.md, trades.csv, equity.csv, ranking.csv, engine rejections and filter-rejections.csv. Source results/yahoo-pilot is a data-acquisition run including warmup and must NOT be compared directly with A; only A/B/C share evaluation dates. The GitHub run summary shows the comparison table. Full per-variant trade tables are in artifacts to avoid oversized summaries. Existing current-news reporting remains available in the old workflow; the new comparison uses no news and cannot use current headlines to approve old entries.

Concentration diagnostics exclude the recorded best trade/ticker P&L arithmetically; these are sensitivity attributions, not portfolio reruns after removing signals. Defaults are preselected hypotheses, not optimized or research-proven penny-stock edges. Positive results require cost stress tests and an untouched future/date holdout. October results already influenced strategy choice. This commit does not implement ORB, volume-sequence variant D, quote-spread filters, automatic optimization, or holdout validation. Hosted tests and actual network runs have not been verified by the assistant.
