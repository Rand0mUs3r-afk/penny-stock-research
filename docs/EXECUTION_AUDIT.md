# Execution audit v3

Main's shared engine now omits the redundant execution-candle completed-volume entry condition. Share sizing still uses only the previous completed candle volume. Whole-dataset quality validation still rejects zero-volume input and the acquisition pipeline still selects complete sessions retrospectively. Thus this fixes the direct entry decision check, NOT all data-selection look-ahead. Raw next-open below the stop now rejects entry even if an adverse entry-cost adjustment would have lifted it above the stop.

Exit labels are stop, stop_and_target_same_bar, gap_through_stop, target, and session_end. Stop/target collisions remain conservative stop-first. A data gap while holding a position fails the run explicitly rather than guessing that the position survived. Missing-close and unclosed-position safeguards remain. No missing candles, partial fills or halt-resumption fills are fabricated.

Each result includes engine_version=execution-audit-v3, execution_audit records and cost_attribution totals. For the SAME filled trades: gross_price_pnl = shares*(raw_exit-raw_entry); spread cost = shares*(raw_entry+raw_exit)*spread_bps/20000; slippage cost = shares*(raw_entry+raw_exit)*slippage_bps/10000; subtract both fees to reconcile net P&L. This is accounting attribution, NOT an independent zero-cost-strategy simulation. Targets, size, risk and trade paths themselves depend on costs.

Signal/order timestamps identify the completed signal boundary. Entry is modeled at the next bar open with no latency. Session-end exits have the modeled close timestamp; other exits have five-minute lower/upper bounds, since candle ordering and exact execution time are unknown. Holding durations are correspondingly bounded. Session-end handling remains a modeled assumption, not proof a close order could fill.

Research diagnostics v2 appends a cost summary and per-trade execution table, exports execution-audit.csv, and preserves execution details in run.json. Older generic research-v2 warning strings are superseded ONLY for the direct execution-bar volume check by the recorded engine version and appended report; other limitations still apply. Existing trade-model/CSV fields remain compatible. Other main workflows share the updated engine but need not display the new audit CSV automatically. The experiment branch is not modified and still has its earlier engine until explicitly updated.

Still outstanding: true OTC data/execution, quote-level spreads, partial-session fills, real liquidity/queue modeling, point-in-time universe, zero-latency realism, settlement restrictions, configurable cost-stress reruns and holdout/walk-forward validation. No profit guarantee. Tests cover cost reconciliation, stop labels, raw-open invalidation, timing bounds, volume sizing independence and unresolved gaps; hosted tests and provider runs have not been verified by the assistant.
